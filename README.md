## Как работать с курсом

> **Каждый модуль сдаётся отдельно.** Для каждого модуля создаётся **своя отдельная ветка** и **свой отдельный Pull Request** (PR). Так тесты проверяют только тe задания, которые вы сдаёте сейчас, и преподаватель видит прогресс по модулям.

**1. Клонируйте репозиторий**
```bash
git clone https://github.com/DKPokidov/python_basic_course.git
cd python_basic_course
```

**2. Создайте отдельную ветку для модуля**

Название ветки — ваши **имя и фамилия латиницей** и **номер модуля** (подчёркивание вместо пробела):

```bash
git checkout -b student/ivan_petrov_m1
```

> Пример: если вас зовут Иван Петров и вы сдаёте модуль 1 — ветка `student/ivan_petrov_m1`. Для модуля 2 — `student/ivan_petrov_m2`, и так далее. Имя из ветки появится в отчётах о проверке, а номер модуля помогает отличать ваши PR друг от друга.

**3. Выполняйте задания этого модуля**
- Откройте задание в VS Code или Jupyter Notebook
- Напишите решение в месте `# НАПИШИТЕ ВАШ КОД ЗДЕСЬ`
- Сохраните файл

> Работайте только с файлами **одного** модуля. Задания других модулей на этой ветке не трогайте — для них будут свои ветки и свои PR.

**4. Отправьте работу**
```bash
git add .
git commit -m "Выполнены задания: модуль N"
git push origin student/ivan_petrov_mN
```

**5. Создайте Pull Request** из этой ветки в `master` (инструкция ниже)

**6. Закончив модуль — создайте новую ветку для следующего**

Чтобы начать следующий модуль, обновите код курса и создайте новую ветку:

```bash
git checkout master
git pull origin master
git checkout -b student/ivan_petrov_m2   # для модуля 2
```

> Не продолжайте задания следующего модуля в старой ветке — каждый модуль живёт в своей ветке и сдаётся своим PR.

> Подробную инструкцию по работе с Git и GitHub смотрите в лекции: [`01_python_basics/lectures/13_работа_с_git_и_github.md`](01_python_basics/lectures/13_работа_с_git_и_github.md)

## Как создать Pull Request: пошаговая инструкция

Pull Request (PR) — это запрос на объединение вашей ветки с заданиями в основную ветку `master`. Именно через PR вы сдаёте работы: автоматические тесты проверят ваши решения при каждом изменении.

> Перед созданием PR убедитесь, что вы уже выполнили шаги 1–4 из раздела выше: склонировали репозиторий, создали ветку и сделали `git push`.

### Шаг 1. Откройте страницу Pull Requests

1. Зайдите на страницу репозитория курса: **[github.com/DKPokidov/python_basic_course](https://github.com/DKPokidov/python_basic_course)**
2. Нажмите вкладку **«Pull requests»** в верхнем меню
3. Нажмите зелёную кнопку **«New pull request»**

### Шаг 2. Выберите ветки

На странице создания PR выберите две ветки:

| Поле | Что выбрать |
|------|-------------|
| **base:** (слева) | `master` — основная ветка курса |
| **compare:** (справа) | `student/ivan_petrov_m1` — ваша ветка с решениями модуля |

> Если в списке нет вашей ветки — значит вы не сделали `git push origin student/ivan_petrov_m1`. Вернитесь в терминал и выполните push.

### Шаг 3. Заполните форму

1. В поле **Title** (заголовок) напишите, например: «Выполнены задания: модуль 1»
2. В поле **Description** (описание) по желанию опишите, что сделали
3. Убедитесь, что написано **«Able to merge»** — это значит, что конфликтов нет

### Шаг 4. Создайте Pull Request

Нажмите зелёную кнопку **«Create pull request»**.

### Шаг 5. Что происходит после создания

- Автоматически запускаются **тесты**: проверка решений (`pytest`) и стиля кода (`flake8`)
- Результаты вы увидите внизу страницы PR в блоке **«Checks»** (зелёная галочка ✅ — всё прошло, красный крест ❌ — есть проблемы)
- Если тесты не прошли — откройте отчёт, найдите проблемные задачи, исправьте решение и повторно выполните:
  ```bash
  git add .
  git commit -m "Исправление: модуль N"
  git push origin student/ivan_petrov_m1
  ```

### Как отправить исправления в уже открытый PR

Отдельный PR создавать не нужно. Всё просто:

1. Внесите правки в файлы на своей ветке
2. Сохраните и закоммитьте:
   ```bash
   git add .
   git commit -m "Исправления после проверки"
   git push origin student/ivan_petrov_m1
   ```
3. Изменения автоматически появятся в уже открытом Pull Request, и тесты запустятся заново

## Автоматические тесты

При каждом Pull Request запускаются тесты:
- Проверка корректности решений (`pytest`)
- Проверка стиля кода (`flake8`)

### Как запускать тесты только по своим заданиям

Не нужно запускать все тесты курса сразу — проверяйте только ту тему, которую сейчас выполняете. Для этого укажите **номер своей папки** в команде.

Перед запуском убедитесь, что:

- вы перешли в папку репозитория (`cd python_basic_course`)
- установлены зависимости: `pip install -r requirements.txt`

Запуск для **вашего** модуля:

```bash
python -m pytest tests/test_01_python_basics -v   # модуль 1
```

Вместо `test_01_python_basics` подставьте свою папку из таблицы:

| Ваш модуль | Тесты для запуска |
|------------|-------------------|
| Модуль 1 | `tests/test_01_python_basics` |
| Модуль 2 | `tests/test_01_python_basics` |
| Модуль 3 | `tests/test_02_python_structures` |
| Модуль 4 | `tests/test_03_control_flow` |
| Модуль 5 | `tests/test_03_control_flow` |
| Модули 6–9 | `tests/test_04_paradigms` |
| Модуль 10 | `tests/test_05_api` |

> Что значат цифры в выводе: зелёные **PASSED** — задание выполнено верно, красные **FAILED** — есть ошибка. Смотрите текст ошибки и исправляйте решение.

### Как запустить тест отдельной задачи

Не обязательно гонять весь модуль — можно проверить **конкретную задачу**. Нужно знать лишь имя файла теста.

Алгоритм:

1. **Найдите имя файла вашей задачи** — например, вы решаете задание `task1_survey.py`
2. **Определите папку тестов вашего модуля** — по таблице выше (для модуля 1 это `tests/test_01_python_basics`)
3. **Запустите тест**, указав путь к файлу теста. Файл теста называется так же, как задание, но с приставкой `test_`:

```bash
python -m pytest tests/test_01_python_basics/test_task1_survey.py -v   # задачи task1_survey
```

Разбор команды:

| Часть | Что значит |
|-------|------------|
| `python -m pytest` | Запуск pytest |
| `tests/test_01_python_basics/` | Папка тестов модуля 1 |
| `test_task1_survey.py` | Тест именно вашей задачи (задача `task1_survey` → тест `test_task1_survey`) |
| `-v` | Подробный вывод |

Примеры для других задач модуля 1:

```bash
python -m pytest tests/test_01_python_basics/test_task3_coins.py -v       # задача task3_coins
python -m pytest tests/test_01_python_basics/test_task6_call_duration.py -v  # задача task6_call_duration
```

> Такой запуск удобен, когда вы правите одну задачу и не хотите ждать проверку всего модуля. Если тест показал **PASSED** — задача решена верно.

Проверка стиля кода (`flake8`) запускается автоматически при Pull Request, локально её можно выполнить так:

```bash
python -m flake8 0*/practice/
```
