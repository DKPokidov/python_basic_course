# Работа с Git и GitHub

> Пошаговое руководство по основам систем контроля версий: зачем нужен Git, как зарегистрироваться на GitHub и как сдавать домашние задания.

---

## Что такое Git и зачем он нужен

**Git** — это система контроля версий. Простыми словами, это программа, которая **следит за изменениями** в ваших файлах и **хранит всю историю** этих изменений.

Представьте, что вы пишете курсовую работу и каждая версия хранится в отдельном файле:

```
диплом_финал.docx
диплом_финал2.docx
диплом_финал3_точно.docx
диплом_окончательный_верный.docx
```

Git решает эту проблему: история всех изменений хранится в одном репозитории, и в любой момент можно **вернуться к любой версии**, посмотреть **что именно изменилось** и **кто это сделал**.

### Почему это важно для вас

1. **Безопасность** — код не потеряется, даже если сломаете файл
2. **История** — всегда видно, что и когда вы меняли
3. **Совместная работа** — несколько человек могут работать над одним проектом
4. **Сдача заданий** — именно через Git вы будете сдавать домашние работы

---

## В чём разница Git и GitHub

| | Git | GitHub |
|---|---|---|
| Что это | Программа (работает на вашем компьютере) | Сайт-сервис (облачный репозиторий) |
| Где запускается | Локально, в терминале | В браузере, по адресу github.com |
| За что отвечает | Отслеживание изменений, история версий | Хранение репозиториев онлайн, Pull Request, совместная работа |

> **Аналогия:** Git — это «двигатель» контроля версий, а GitHub — «сервис», который даёт удобный интерфейс для работы с ним в интернете.

## Основные понятия

### Репозиторий (repository)

**Репозиторий** — это папка проекта, за которой следит Git. Все изменения, коммиты и история хранятся здесь.

- **Локальный репозиторий** — на вашем компьютере
- **Удалённый репозиторий** — на GitHub (в облаке)

### Коммит (commit)

**Коммит** — это «снимок» состояния файлов в определённый момент времени. Каждый коммит — это сохранённая точка, к которой можно вернуться.

> Коммит похож на сохранение в компьютерной игре: вы записали прогресс и в любой момент можете загрузиться в эту точку.

### Ветка (branch)

**Ветка** — это отдельная линия разработки. Основная ветка обычно называется `master` или `main`. Для своих заданий вы создаёте **отдельную ветку**, чтобы не мешать другим.

### Ветка и её состояниe

- `HEAD` — указатель на последний коммит текущей ветки
- «Коммит закоммичен» — изменения зафиксированы и добавлены в историю

### Клонирование (clone)

**Клонирование** — это копирование удалённого репозитория на ваш компьютер:

```bash
git clone https://github.com/DKPokidov/python_basic_course.git
```

### Добавление файлов (add)

**`git add`** — добавляет файлы в «подготовленную» зону (staging area), чтобы потом закоммитить их:

```bash
git add .          # добавить все изменённые файлы
git add task1.py   # добавить конкретный файл
```

### Фиксация изменений (commit)

**`git commit`** — создаёт точку сохранения из добавленных файлов:

```bash
git commit -m "Выполнены задания: модуль 1"
```

> К каждому коммиту обязательно пишется **сообщение** (флаг `-m`) — коротко опишите, что сделали.

### Статус (status)

**`git status`** — показывает состояние репозитория: какие файлы изменены, какие уже добавлены, а какие ещё не сохранены:

```bash
git status
```

### Отправка изменений (push)

**`git push`** — отправляет ваши локальные коммиты в удалённый репозиторий на GitHub:

```bash
git push origin student/ваше_имя
```

### Получение изменений (pull / fetch)

- **`git pull`** — загружает изменения с удалённого репозитория и сразу применяет их локально
- **`git fetch`** — загружает изменения, но не применяет (только показывает)

```bash
git pull origin master
```

### Pull Request (PR)

**Pull Request** — это **запрос на объединение** вашей ветки с основной (`master`). Вы создаёте PR на сайте GitHub, и преподаватель видит ваши изменения, может их проверить и **принять** (merge) или **отклонить**.

> Для сдачи домашних заданий вы будете создавать именно Pull Request из своей ветки в `master`.

### Merge (слияние)

**Merge** — это объединение разных веток в одну. Когда преподаватель нажимает **«Merge pull request»**, ваши изменения добавляются в основную ветку.

### Конфликт (conflict)

**Конфликт** возникает, когда одни и те же строки файла менялись в двух ветках одновременно. Его нужно разрешить вручную: выбрать нужный вариант или объединить оба.

### .gitignore

**`.gitignore`** — файл, в котором перечислены папки и файлы, которые Git должен **игнорировать** (не отслеживать). Например, временные файлы, кеши и секретные ключи.

## Регистрация на GitHub

### Шаг 1: Создайте аккаунт

1. Откройте сайт **[github.com](https://github.com)**
2. Нажмите **«Sign up»** (Зарегистрироваться)
3. Введите **email**, придумайте **пароль** и **имя пользователя**
4. Пройдите проверку «Я не робот»
5. Нажмите **«Create account»**

> Имя пользователя (username) будет частью адреса ваших репозиториев. Выбирайте понятное и запоминающееся имя — например из фамилии.

### Шаг 2: Подтвердите email

- GitHub пришлёт письмо с кодом подтверждения
- Введите этот код на сайте, чтобы подтвердить адрес

### Шаг 3: Настройте профиль (по желанию)

1. Нажмите на аватар → **Settings**
2. Добавьте имя, фото или описание — так преподавателю будет проще понять, чья это работа

### Шаг 4: Установите Git на компьютер

- **Windows:** скачайте с [git-scm.com](https://git-scm.com) и установите
- **macOS:** установите с сайта или через `brew install git`
- **Linux:** `sudo apt install git`

> После установки проверьте работу Git командами из раздела ниже.

### Шаг 5: Настройте Git (обязательно!)

Чтобы ваши коммиты были подписаны вашим именем, выполните один раз в терминале:

```bash
git config --global user.name "Ваше Имя"
git config --global user.email "ваш_email@example.com"
```

> Имя и email должны совпадать с теми, что вы указали на GitHub.

## Основные команды работы с терминалом

### Навигация по файлам и папкам

| Команда | Что делает |
|---------|------------|
| `pwd` | Показать текущую папку |
| `ls` | Список файлов в текущей папке |
| `cd папка` | Перейти в папку |
| `cd ..` | Подняться на уровень выше |
| `mkdir имя` | Создать новую папку |
| `touch файл` | Создать пустой файл (macOS/Linux) |
| `rm файл` | Удалить файл |
| `clear` | Очистить терминал |

### Основные команды Git (от «начала» до «конца»)

| Шаг | Команда | Что делает |
|-----|---------|------------|
| 1 | `git clone URL` | Скачать репозиторий на компьютер |
| 2 | `git checkout -b имя_ветки` | Создать и перейти в новую ветку |
| 3 | `git status` | Посмотреть, что изменилось |
| 4 | `git add .` | Добавить изменения |
| 5 | `git commit -m "сообщение"` | Сохранить точку (коммит) |
| 6 | `git push origin имя_ветки` | Отправить на GitHub |
| 7 | `git pull origin master` | Забрать свежие изменения |

### Часто используемые команды

| Команда | Что делает |
|---------|------------|
| `git log` | Показать историю коммитов |
| `git log --oneline` | Компактная история коммитов |
| `git branch` | Список веток |
| `git checkout имя_ветки` | Переключиться на другую ветку |
| `git remote -v` | Показать удалённые репозитории |
| `git diff` | Показать изменения в файлах |
| `git reset HEAD~1` | Отменить последний коммит |

## Последовательность сдачи задания

1. Клонируйте репозиторий курса
2. Создайте ветку: `git checkout -b student/ваше_имя`
3. Выполните задания в нужных файлах
4. Сохраните результат:
   ```bash
   git add .
   git commit -m "Выполнены задания: модуль N"
   ```
5. Отправьте на GitHub:
   ```bash
   git push origin student/ваше_имя
   ```
6. Создайте **Pull Request** из вашей ветки в `master`
7. Дождитесь проверки: преподаватель примет PR или оставит комментарии

> Подробная пошаговая инструкция по созданию Pull Request — в [README репозитория](../../README.md).

## Шпаргалка по Git

```
git clone <url>                    # скачать репозиторий
git status                         # состояние проекта
git add .                          # подготовить все изменения
git commit -m "сообщение"          # создать коммит
git push origin <ветка>            # отправить на GitHub
git pull origin <ветка>            # забрать изменения
git branch                         # список веток
git log --oneline                  # история коммитов
```
